LAPORAN HASIL REVISI PROYEK CIPUTRA SH-1
Sumber acuan: Revisi Proyek Ciputra SH-1(1).docx

1. RINGKASAN PERUBAHAN
- Proyek direvisi berdasarkan konsep Word: desain utama, warna, layout, dashboard, grafik, tombol, print, Excel, dan aset lama dipertahankan.
- Register publik dinonaktifkan total. Pelanggan tidak dibuat sebagai user login.
- Login hanya untuk Admin SH-1, QC, dan Kontraktor.
- Admin SH-1 bisa membuat, mengedit, menonaktifkan, dan reset password akun QC/Kontraktor per proyek.
- Alur keluhan pelanggan dipisahkan dari alur temuan QC.
- QC hanya bisa membuat temuan QC di proyeknya sendiri dan meneruskan ke kontraktor.
- Kontraktor hanya bisa melihat tugas yang diberikan QC dan mengisi jawaban/perbaikan.
- Status pekerjaan dirapikan mengikuti alur baru.
- Deadline kontraktor maksimal 5 hari ditambahkan ketika temuan/keluhan diteruskan ke kontraktor.
- Loading spinner memakai logo assets/Ciputra.png ditambahkan untuk proses halaman, login, submit, workflow, upload, print, dan export/import.
- Security, permission backend, rate limit login, upload security, audit log, backup, deployment, dan dokumentasi ditambahkan.

4. ALUR KERJA BARU BERDASARKAN ROLE
A. Admin SH-1
- Melihat semua proyek dan semua data.
- Mengelola proyek.
- Membuat/edit/nonaktifkan akun QC dan Kontraktor per proyek.
- Validasi/tolak keluhan pelanggan.
- Meneruskan keluhan pelanggan ke QC.
- Monitoring semua progres.
- Print dan export/import Excel.
- Tidak bisa membuat temuan QC.
- Tidak bisa mengisi/mengedit jawaban kontraktor.

B. QC
- Login ke dashboard QC.
- Hanya melihat data proyeknya sendiri.
- Membuat temuan QC untuk proyeknya sendiri.
- Menerima keluhan pelanggan yang diteruskan admin.
- Meneruskan temuan/keluhan ke kontraktor proyeknya.
- Memeriksa jawaban kontraktor.
- Tidak bisa membuat akun.
- Tidak bisa mengisi jawaban kontraktor.

C. Kontraktor
- Login ke dashboard kontraktor.
- Hanya melihat temuan/keluhan yang ditugaskan ke dirinya di proyeknya.
- Mengisi jawaban/perbaikan.
- Menentukan tanggal dan jam rencana perbaikan.
- Upload foto perbaikan.
- Konfirmasi pekerjaan selesai.
- Tidak bisa membuat temuan, validasi keluhan, atau membuat akun.

D. Pelanggan
- Tidak punya akun.
- Tidak bisa register.
- Tidak bisa login dashboard.
- Hanya bisa submit keluhan publik dan upload foto.

5. ALUR KELUHAN PELANGGAN
1. Pelanggan mengisi form publik tanpa login.
2. Status awal: Menunggu Validasi Admin.
3. Admin memeriksa keluhan.
4. Jika ditolak: status Ditolak Admin dan alasan penolakan disimpan.
5. Jika diterima: admin teruskan ke QC sesuai proyek.
6. QC menerima keluhan dan meneruskan ke kontraktor proyek terkait.
7. Saat diteruskan ke kontraktor, deadline 5 hari dibuat.
8. Kontraktor mengisi jadwal, jawaban, dan upload foto perbaikan.
9. QC memeriksa hasil kontraktor.
10. QC meneruskan hasil ke admin untuk keluhan pelanggan.
11. Admin konfirmasi ke pelanggan.
12. Status akhir: Selesai.

6. ALUR TEMUAN QC
1. QC login.
2. QC membuat temuan baru untuk proyeknya sendiri.
3. Status awal: Temuan QC Dibuat.
4. QC meneruskan temuan ke kontraktor.
5. Deadline 5 hari dibuat.
6. Kontraktor mengisi jawaban, jadwal perbaikan, foto, dan status selesai.
7. QC memeriksa hasil.
8. Status akhir: Selesai.
9. Temuan QC tidak perlu validasi admin dan tidak perlu konfirmasi pelanggan.

7. ALUR KONTRAKTOR
1. Kontraktor login.
2. Kontraktor melihat daftar tugas yang diberikan QC.
3. Kontraktor membuka detail.
4. Kontraktor mengisi penyebab, antisipasi, jawaban/keterangan perbaikan.
5. Kontraktor menentukan tanggal dan jam rencana perbaikan.
6. Kontraktor upload foto hasil perbaikan.
7. Kontraktor menyimpan jawaban.
8. Status berubah sesuai progress dan siap diperiksa QC.

8. STATUS PEKERJAAN
Status keluhan pelanggan:
- Menunggu Validasi Admin
- Ditolak Admin
- Diterima Admin
- Diteruskan ke QC
- Diteruskan ke Kontraktor
- Menunggu Jadwal Perbaikan Kontraktor

- Selesai Dikerjakan Kontraktor

- Jadwal Perbaikan Diajukan Kontraktor

- Selesai Dikerjakan Kontraktor
- Diperiksa QC
- Selesai

9. DEADLINE 5 HARI
- Deadline otomatis dibuat ketika QC meneruskan keluhan/temuan ke kontraktor.
- Untuk keluhan pelanggan, dasar deadline adalah tanggal diterima admin jika ada, atau tanggal saat diteruskan.
- Untuk temuan QC, dasar deadline adalah tanggal diteruskan QC ke kontraktor.
- Indikator: Normal, Mendekati Deadline, Melewati Deadline.

11. SECURITY YANG DITAMBAHKAN
- Register publik dinonaktifkan di frontend dan backend.
- Role backend divalidasi pada setiap endpoint penting.
- Admin, QC, dan Kontraktor dibatasi sesuai proyek dan tugasnya.
- Password memakai password_hash dan login memakai password_verify.
- Rate limit login menggunakan tabel login_attempts.
- Session cookie memakai HttpOnly, SameSite, dan Secure jika HTTPS.
- Upload dibatasi JPG/PNG/WEBP dan ukuran maksimal.
- Nama file upload dibuat random.
- Folder uploads memiliki .htaccess untuk mencegah eksekusi script.
- Error SQL tidak ditampilkan ke frontend.
- Security headers dasar ditambahkan.
- Audit log ditulis ke database dan logs/app.log.

Catatan jujur:
- CSRF token khusus untuk semua POST/PUT/DELETE belum dibuat penuh. Validasi role/backend sudah diterapkan, tetapi CSRF token masih perlu ditambahkan bila ingin production-grade.
- Row Level Security yang diterapkan adalah validasi backend berbasis proyek/role, bukan fitur RLS database seperti PostgreSQL.
